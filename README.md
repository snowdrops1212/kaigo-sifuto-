# あかり シフトプランナー

介護施設向けのシフト作成・調整用の試作アプリです。HTML・CSS・JavaScriptのみで動作します。

## 起動

Python が使える場合：

```sh
python -m http.server 8765 --bind 127.0.0.1 --directory dist
```

ブラウザーで http://127.0.0.1:8765/ を開きます。ほかの静的ファイル用サーバーでも起動できます。公開する場合のルートは `dist/` です。

## 主な機能

- 希望休・有給を職員と日付を指定して登録。別月の日付も登録可能
- シフト調整ページ上部に希望休・有給の登録欄を集約
- 登録欄の下に、当月の職員別希望一覧を表示。希望休・有給を分けて日付順・曜日付きで表示し、登録や月変更で更新
- 希望休欄の下に会議日を登録・解除。会議日は在籍中で職種が「管理者」の職員全員をB勤務として自動作成。休み希望・固定勤務・勤務不可曜日・夜勤明けとの矛盾は上書きせず作成を停止
- 条件・プロンプト画面に会議日とB勤務の条件を自動表示。登録した会議日は月別にJSON保存され、旧形式のデータも読み込み可能
- 対象月の前月・翌月ボタンと、登録日のカレンダーの月・年選択で別月へ移動
- 職員・条件ページ上部で月の作成条件を編集（独立した「希望休・月の条件」ページは削除）
- 希望休、固定勤務、勤務可能曜日、在籍期間などを考慮したシフト案の自動作成
- 手動調整・固定・勤務交換・元に戻す
- シフト表の下に日別の勤務記号別人数と、B・C・D・d・G・Iの8時間換算を統合。日付の列と横スクロールを共有
- 「縦を全体表示」で全職員・人数集計・8時間換算が縦に収まるよう縮小（日付の横スクロールは利用可能）
- 「表を画面いっぱいに表示」と「文字を大きくする」で表示を切替。画面いっぱいの表示は通常画面に戻るボタンまたはEscで終了
- 4月〜翌年3月の有給登録日数を表示（希望とシフトの同じ日は重複計上しません）
- 職員・条件の編集、JSON保存・読込、CSV出力
- 職員ごとの「編集」「削除」。削除前に全月の対象データの件数を確認し、キャンセル・元に戻す・やり直すに対応

「利用予定」と「日ごとの利用予定・必要人数」の入力欄は削除しています。保存済みの利用者・日別設定はJSONの互換性のため保持します。過去に設定した日別B・C・Dの必要人数は引き続き月の設定より優先され、条件の設定内容まとめから確認できます。

## 保存と取り扱い

入力内容は画面内でのみ保持します。終了前に「データを保存」でJSONをダウンロードし、次回「データを開く」で読み込んでください。サーバー保存・複数人共有・実際の取得実績の確定は未対応です。

サンプル職員のみを収録しています。実際の職員や利用者の情報、保存したJSON、勤務実績をこのリポジトリへ追加しないでください。認証情報や公開サービス固有の設定は含めていません。

## サンプルから実際の職員への切り替え

- 初期設定では「職員・条件」ページの職員一覧にある「編集」で、サンプルの氏名・勤務条件を変更できます。同じ職員IDの希望休・有給・シフト・個別設定は引き継がれます。
- 引き継ぎたくない場合は「職員を追加」で実際の職員を登録し、不要なサンプルの横にある「削除」を押してください。確認画面で取り消せます。
- 削除するのは、その職員と全月のその職員の希望休・有給希望・勤務セル・固定・個別設定です。有給の年間集計からも外します。他の職員、利用者データ、会議日、月の条件は保持します。条件文の氏名やメモは自動で消さないため、必要に応じて見直してください。
- 削除前に「データを保存」でバックアップしてください。削除直後は「元に戻す」で復元できます（画面内の履歴は最大40回）。編集・削除後の状態もJSONで保存してください。
- 実際の退職者の履歴を残す場合は、削除せず「編集」で最終勤務日を設定してください。管理者を削除した場合、登録済みの会議日の条件を満たせなくなることがあります。

## 制約

- 法定配置への適合を保証するものではありません。施設の担当者による確認が必要です。
- 自動作成は試行的な組み合わせ探索であり、すべての条件の充足・最適解を保証しません。
- 条件文章の自動反映は定型の5項目のみです。自由記述の解釈には対応していません。
- 会議日は文章解析とは別に、登録欄の指定を自動作成に直接適用します。登録・解除だけでは作成済みシフトを変更しないため、反映するには再作成してください。
- 「正社員は月176時間以上」「夜勤D→d→EのEとは別に月9日のE」を条件文へ追加しています。この2条件の自動割当・充足判定は保留です。正社員の区分と時間の数え方を確認する必要があり、現行のD・d各8時間換算では、31日の月に通常E9日と夜勤後E1日を取ると最大168時間になります。条件を勝手に緩和しません。
- 希望休の登録だけでは作成済みシフトは変わりません。再作成または手動調整で反映してください。
- 有給の年度合計は取得予定を含む登録日数です。

## テスト

Node.js で実行します。依存ライブラリのインストールは不要です。

```sh
node test.cjs
node test-conditions.cjs
node test-paid-leave.cjs
node test-request-form.cjs
node test-meetings.cjs
node test-members.cjs
```

`test-request-form.cjs` は簡易DOMを使うロジックテストです。実ブラウザーの見た目を検証するものではありません。

`test-meetings.cjs` は、会議日の管理者B勤務、複数管理者、休み希望・固定勤務との矛盾、前月末夜勤、在籍期間、旧保存データ、会議日の形式を検証します。

`test-members.cjs` は、削除対象の集計、全月の関連データ削除、他職員・条件・会議日の保持、類似IDの分離、保存データの読み戻し、年間有給集計、人数集計、管理者不在、最後の職員の削除を検証します。確認・キャンセル・元に戻す・やり直す・氏名のエスケープ・空の一覧は `test-request-form.cjs` で検証します。
